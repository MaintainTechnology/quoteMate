The one thing that surprises everyone. The Front Desk forwards to the receptionist by POSTing /api/receptionist/simulate with an x-sim-key header. That endpoint reads like a test harness, but it is the production channel — which is why SMS_SIMULATE_ENABLED=1 is set in prod. It synthesises a Twilio-shaped request, signs it with the service's own auth token, and calls the same handler a genuine callback would hit. There is no signature bypass anywhere.

Two known inconsistencies, so you are not surprised while reading. The photo-request template has an ev_charger branch in quotemate-automation that frames the photo as required, but the receptionist's copy has no such branch and falls through to four randomised variants that all say "optional" — the opposite of what the readiness gate enforces. And the receptionist's quote-readiness.ts is 549 lines against the platform's 670: ev_photo blocking and the clarify_gate_count cap were never ported across.
