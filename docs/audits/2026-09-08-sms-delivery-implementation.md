# SMS delivery implementation evidence

Implements the delivery/public-page/media portion of the reliability audit: F10–F12, F19, F22 and F25. Local implementation evidence only; production migration, deployment and controlled carrier verification remain release gates.

## Behaviour and contracts

- `sql/migrations/199_sms_delivery_outbox.sql` adds the service-only durable outbox, fenced enqueue, atomic claims, receipt transitions, tenant-scoped recovery and atomic plan-request reuse. It depends on migration 198. Outbound intents are written before provider I/O. A lost/ambiguous provider response or abandoned sending lease becomes `unknown`, which cannot automatically resend. Failed and unknown messages remain visible with `requires_attention`.
- `lib/sms/dispatch.ts` sends every audience through the outbox. `deliveryKey` identifies a named operation; `withSmsDeliveryContext` supplies turn/tenant/conversation/work ownership to nested calls. Explicit named keys are preferred; the fallback combines the processing job ID (or turn ID) with a logical payload digest, so outer retry wrappers reuse one intent and different stages do not collide. Persistent `mediaKey` values or URL paths exclude renewed signed credentials from identity. The original persisted payload is authoritative on replay. Independent calls without a job, turn or explicit key create distinct intents.
- Successful provider acceptance is recorded as `accepted`, separately from signed `delivered` receipts. Failed/unknown sends do not enter accepted conversation history. The database classifies legacy compatibility writers against outbox evidence and suppresses duplicate transcript inserts.
- `POST /api/sms/status` validates the exact website URL, all provider parameters, account and Twilio signature. Receipt updates are fenced by attempt token/SID and monotonic. A failure callback arriving before the original POST response cannot be overwritten as success.
- `recoverSmsOutbox` and `/api/cron/sms-outbox` process safe retries and reconcile stale messages using read-only provider queries. `/dashboard/sms-delivery` and the tenant-authenticated `/api/tenant/sms-delivery` expose status and explicit recovery. Unknown/accepted outcomes and STOP recipients cannot be retried through this endpoint.
- `lib/sms/mms.ts` restricts authenticated fetches to the configured account's canonical Twilio media path. Redirects are manual and limited to the secured Twilio CDN without credentials. Fetches have a timeout, a 5 MB streamed-byte ceiling, MIME/signature checks and full Sharp decoding under a 25-million-pixel ceiling. The fleet must include Sharp 0.34.5 and preserve MIME metadata.
- All seven public token-page entry functions now distinguish an absent row from a resolved database/contract error. Database errors produce a recoverable view and safe correlation identifier; thrown failures reach the quote error boundary. `verifyPublicQuoteSchema` probes seven families with zero-row, three-second-bounded queries for the fleet/release readiness gate.
- Plan, air-con and commercial-paint pages require persisted `released_at` before returning customer prices. The public plan PDF route enforces the same gate. Actual page tests cover null/missing approval and historical non-null release; rows with no release evidence are held, never guessed approved.
- The painting release sender uses only the owning tenant's configured number, canonical website origin and durable named send request. It requires persisted approval and returns outbox ID/status for recovery. Carrier rejection, ambiguous acceptance and compose failure do not revoke existing approval.
- Plan upload requests are serialised per tenant/customer and reuse persisted tokens. Migration 210 commits input metadata, a platform `plan` job and the request receipt atomically before upload HTTP 202. New input storage paths include their SHA-256 hash. The scheduled platform worker checkpoints model output, the uniquely identified extraction, pricing, report and customer body. Saved extraction results survive a lost checkpoint response. Legacy stranded requests receive work receipts; existing drafts, counts, prices and public tokens are preserved without rerunning the model or repricing them. Worker writes are fenced by ownership and input version.
- Plan analysis saves a durable tradie review task and queues an honest awaiting-approval customer status before marking the plan complete; it cannot send the price, public PDF link or direct signed report attachment before approval. Extraction/review/outbox persistence failure remains visible in the work queue and request; the worker retries within its existing eight-attempt budget. Provider notification failures remain independently visible in the outbox.
- `publicWebOrigin`/`publicWebUrl` reject missing, local production, credential-bearing and API-only origins. Startup/readiness and caller migrations must use this helper consistently; it is not evidence of deployed environment compatibility.
